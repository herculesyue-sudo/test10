# 05 · 私域轉化 SOP 與話術

> 所有話術均以「不作疾病治療聲稱、不介入用藥、不作療效承諾」為前提設計。
> 客服每一句都可能被截圖，**私訊的合規要求與公開廣告完全相同**——
> 香港《不良廣告（醫藥）條例》管的是「廣告」，一對一推銷訊息同樣落入範圍。

---

## 一、漏斗與轉化路徑

```
公開內容 → 官網／自測問卷 → 留資（姓名＋WhatsApp＋同意書）
   → 自動歡迎訊息 → 人工分流（24 小時內）
   → Tier 1 評估預約（HK$680）→ 註冊營養師諮詢
   → 個人化報告 → Tier 2 訂閱提案 → 成交 → 交付 → 續訂／轉介
```

**關鍵設計：產品在漏斗中第一次出現，是在營養師一對一諮詢的階段，而不是之前。**
之前所有環節，賣的是評估與服務。

## 二、首次接觸：自動歡迎訊息（可自動化）

```
你好，我係【品牌名】嘅健康顧問 XX 👋

多謝你完成代謝健康自測。你嘅報告已經 email 咗俾你，請查收（記得睇埋 spam）。

想先講清楚兩件事：
1️⃣ 我哋提供嘅係營養與生活習慣管理服務，唔係醫療服務，
   亦都唔會取代你嘅主診醫生。
2️⃣ 任何藥物或胰島素嘅調整，一定要由你嘅醫生決定，我哋唔會作任何建議。

如果你想有人幫你睇實際情況、度身整一個飲食同生活計劃，
我哋有一個 60 分鐘嘅代謝健康評估，由香港註冊營養師做。

有咩想問，隨時 whatsapp 我 🙂

—
【收集個人資料聲明】你提供嘅資料只用於提供本服務及跟進，
不會轉交第三方作促銷用途。你可隨時要求查閱、更正或刪除。
如你同意日後收取我哋嘅健康資訊及推廣，請回覆「同意」。
```

**注意最後一段**：香港《個人資料（私隱）條例》第VIA部要求直接促銷須取得**明示同意**，
把它做成一個明確動作（回覆「同意」），並記錄下來。

## 三、分流：三種來人，三種處理

| 類型 | 識別 | 處理 |
|---|---|---|
| **A · 自己有代謝問題** | 提及自己驗血、指數、體重 | 標準路徑 → Tier 1 評估 |
| **B · 幫家人問** | 「我爸媽…」 | 走家人視角話術，強調「幫佢準備好去見醫生」，可推家庭方案 |
| **C · 高風險個案** | 一型糖尿病、已用胰島素、有併發症（腎、眼、足）、孕婦、兒童、正服多種藥 | **不接、不賣產品**。回覆標準拒絕話術，建議求醫。記錄在案 |

### C 類標準回覆（必須逐字使用）

```
多謝你信任同分享。

以你講嘅情況，我哋唔適合提供服務，亦都唔會建議你用任何保健產品。
原因係你嘅情況需要由醫生密切監察，任何飲食或補充品嘅改變都可能影響
你嘅藥物劑量，呢個唔係我哋可以處理嘅範圍。

我嘅建議係盡快同你嘅主診醫生／內分泌科專科傾，
話俾佢知你嘅擔憂，睇下可唔可以轉介營養師或者糖尿病護士。

醫管局有糖尿病專科服務，你可以問你嘅家庭醫生攞轉介。

真心希望你身體好返 🙏
```

**這條話術會令你少做生意。它同時是你最重要的一條保險。**
文件中那位一型糖尿病患者，正正屬於 C 類。

## 四、常見問題應對（客服必背）

| 客人問 | ✗ 不能答 | ✓ 標準答法 |
|---|---|---|
| 「食完會唔會降到血糖？」 | 「會，好多人都降咗」 | 「我唔可以講任何產品有降血糖嘅作用，法例唔容許，我亦都唔想俾錯誤期望你。我哋做嘅係飲食同生活習慣管理，血糖嘅醫療處理係你醫生嘅範圍。」 |
| 「有冇人食完減咗藥？」 | 任何肯定回答 | 「藥物調整一定要醫生決定。我哋見到嘅係客人對自己食嘅嘢了解多咗，覆診時同醫生溝通順暢咗。」 |
| 「呢個係咪藥嚟？」 | 「係，好勁㗎」／「唔係，係保健品嚟，冇副作用」 | 「呢個係天然草本嘅口服滴飲，喺香港嘅法律身份係食品，唔係註冊藥物。所以佢唔可以、亦都唔應該用嚟取代任何藥物。」 |
| 「有冇副作用？」 | 「純天然，冇副作用」 | 「任何入口嘅嘢都可能同你食緊嘅藥有相互作用，所以我哋要求每位客人都話俾主診醫生知，並提供完整成分表。」 |
| 「有冇臨床實驗？」 | 「有，100% 有效率」 | 「冇。呢個係保健食品，唔係經過臨床試驗嘅藥物。如果有人同你講有 100% 有效率，你應該懷疑佢。」 |
| 「可唔可以寄去內地？」 | 任何寄件安排 | 「唔可以。呢個產品冇內地嘅進口批文，寄入去係違法嘅，我哋唔會做。如果你返香港，可以喺香港購買同使用。」 |
| 「點解咁貴？」 | 比價、貶低同行 | 「我哋賣嘅係一個管理計劃：註冊營養師跟進、CGM 數據、定期報告。單支產品嘅價錢喺市面上你可以自己比較，但呢個計劃嘅價值係有人一直跟住你。」 |
| 「可唔可以平啲？」 | 隨意折扣 | 「價錢係固定嘅。如果預算係考慮，我建議先做 HK$680 嘅評估，睇下值唔值得再繼續。」 |

## 五、Tier 1 評估的交付結構（60 分鐘）

| 時段 | 內容 |
|---|---|
| 0–5 分 | 知情同意、免責說明、確認已／將告知主診醫生 |
| 5–20 分 | 飲食記錄回顧（客人預先提交 3 日記錄） |
| 20–35 分 | 生活習慣：睡眠、運動、工作模式、外食頻率 |
| 35–50 分 | 個人化建議：具體到「你返工附近嗰間茶餐廳可以點叫」 |
| 50–58 分 | 行動計劃（3 項，不多於 3 項）＋ 下一步選項說明 |
| 58–60 分 | 問答 |

會後 48 小時內交付書面報告。**報告不得包含診斷、不得建議藥物調整、
不得預測血糖或 HbA1c 數值。**

產品若適用，由營養師在此環節按個別情況提出，並須記錄理由。
**若營養師認為不適用，必須可以不提。** 這一點寫進其合約。

## 六、可自動化與不可自動化的邊界

| 環節 | 自動化 | 工具 |
|---|---|---|
| 內容草稿生成 | ✅ 全自動 | LLM + 選題庫 + 品牌語調提示詞 |
| **合規詞掃描** | ✅ 全自動（強制關卡） | [compliance/check.py](../compliance/check.py) |
| 內容審核 | ❌ 必須人工 | 有專人簽核，留記錄 |
| 發布 | ⚠️ FB／IG 可用官方排程；**小紅書必須人手** | Meta Business Suite |
| 留資接收與標籤 | ✅ 全自動 | 表單 → CRM webhook |
| 歡迎訊息、預約提醒、報告交付通知 | ✅ 全自動 | WhatsApp Business API（模板訊息需預先審批） |
| **健康問題回覆** | ❌ 絕不自動化 | 人工，且必須受訓 |
| **產品建議** | ❌ 絕不自動化 | 只可由註冊營養師在諮詢中提出 |
| 續訂提醒、滿意度調查 | ✅ 全自動 | CRM |
| 數據報表 | ✅ 全自動 | 見下 |

### 建議技術棧（輕量、香港可用）

```
官網／落地頁     : Webflow 或 WordPress
表單／自測       : Typeform / Tally
CRM              : HubSpot 免費版起步，或 Notion + Make
訊息             : WhatsApp Business API（透過 360dialog / Twilio）
排程             : Meta Business Suite（FB/IG 原生）
合規閘門         : 本倉庫 compliance/check.py，接入 CI 或 Make webhook
數據             : Google Sheets + Looker Studio
```

**不要買**：小紅書養號／群控／自動私訊工具。這些工具的存在本身就是封號特徵。

## 七、客服守則（貼在牆上）

1. 我唔係醫護人員，我唔做診斷、唔講療效、唔掂藥物。
2. 任何一句我唔肯定合唔合規嘅說話，我唔講，我問主管。
3. 客人提到一型糖尿病、胰島素、併發症、懷孕 → 立即走 C 類流程。
4. 客人問寄內地 → 直接講唔做，唔研究、唔轉介、唔「幫你諗辦法」。
5. 客人講低血糖、暈眩、視力突變 → 立即叫佢求醫，並記錄成不良事件。
6. 我講嘅每一句，都當會被截圖出街。
